The verification database

  • verify-db-YYYY-MM, one GitHub release a month: each run's pairs against the surface stations (sfc_<init>.parquet), the radiosondes (raob_) and Stage IV (rain_), their sums (stats_, stn_), and the ensembles' cases and sums (ens-sfc-<model>_, ens-raob-, ens-rain-, ens-stats_, ens-stn_, ens-rel_).
  • verify-z500-YYYY-MM: every model's 500 hPa height on the 1.5° grid (z500-<model>_, ensemble means ens-z500- and members ens-z500m-), ERA5's (era5-z500_) and each run's anomaly correlations (acc_).
  • verify-weeks-YYYY, one release a year, for weeks 1–5: each Monday and Thursday GEFS run's weekly anomaly maps before the drift correction and the daily zonal means the correction is estimated from (wk-gefs_<init>.npz), each GEPS run's weekly anomaly maps (wk-geps_) and ERA5's 00Z and 12Z fields a month a file (wk-era5_<YYYYMM>.npz), all on the 1.5° grid; the ERA5 1991–2020 normal they are taken against is verify-clim-weeks-v1.
  • The code that writes and reads it: scripts/verify (verifydb.sh lists and fetches it), scored with mverify.
